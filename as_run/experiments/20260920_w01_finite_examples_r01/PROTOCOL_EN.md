# Protocol: W0–W1 finite examples

Created: 20 September 2026 (actual creation date).

**Protocol frozen before implementation was written and before any outcome was observed.**

## 1. Question this package answers

Does a fresh implementation of the joint-opportunity algebra specified in
[`docs/METHOD_SPEC_EN.md`](../../docs/METHOD_SPEC_EN.md) reproduce independently derived answers on the six
representation cases and eight assistance-accounting cases required by master plan §10?

This is a test of **analytical correctness only**. It is the first of the eight claim classes in
[`docs/RESEARCH_QUESTION_EN.md`](../../docs/RESEARCH_QUESTION_EN.md) §4 and implies none of the other seven.

## 3. Resource limits

Combined W0–W1 cap: **one working day and 30 CPU minutes** (master plan §10).

Prohibited in this package, and not performed: SUMO invocation; any simulator episode; any optimizer
update; any checkpoint load; any TEST-split access; any import or execution of a legacy runtime module;
any unattended campaign or heartbeat; any external dependency installation.

Implementation uses the **Python standard library only**. Dependency pinning is deferred to W2 (D16).

## 4. Acceptance rule — fixed before outcomes

Let `NF` = 6 representation cases and `NA` = 8 assistance cases, each with every assertion listed in the
fixture.

- **PASS** for a case iff **every** asserted field matches the frozen expectation exactly. Interval
  endpoints and scalar margins compare within an absolute tolerance of `1e-9`; verdicts, labels and
  booleans compare for exact equality.
- **FAIL** for a case iff any asserted field differs.
- **ERROR** iff the implementation raises or does not terminate.

The package reports the outcome of **every** case, including failures and errors. No case is removed,
retried after modification, or excluded from the denominator. A case that fails stays in the record with
its observed value.

**Gate statement, fixed now:** the W1 analytical-correctness gate is `SUPPORTED` only if
`14 / 14` cases PASS **and** the cross-checks in §5 hold. Any other result is `NOT_SUPPORTED` or
`INCONCLUSIVE`, decided in `SCIENTIFIC_DECISION.md`, and does not permit dependent work.

## 5. Cross-checks that must also hold

These are properties, not cases; they are asserted in the test suite.

1. **Pairwise unsoundness (Claim P1).** On F1 the joint predicate returns `REJECTED` while the pairwise
   relaxation returns `SUPPORTED`.
2. **Hull rejection.** On F3 the hull relaxation returns a non-empty window while the exact computation
   returns empty.
3. **Dwell uses max-contiguous.** On F2, raising the dwell requirement to 3.0 must remove `SUPPORTED`,
   although the total window width is 4.0.
4. **Rule asymmetry.** F3 with `OVER` labels yields `REJECTED`; the identical sets with `UNDER` labels
   yield `UNKNOWN`.
5. **Rejection dominates ignorance.** F1 with `PREDICTION` labels yields `UNKNOWN` temporally and
   `REJECTED` jointly.
6. **Arm degeneracy.** The `J1` selection code path run with `switch_margin = 0.0`,
   `max_commit_duration = 1`, `unknown_tolerance = 0` reproduces the `J0` trace exactly.
7. **Canonicalisation is idempotent and total** on randomly generated interval unions.
8. **No unknown becomes supported.** No combination of verdicts containing `UNKNOWN` and no `REJECTED`
   yields `SUPPORTED`.
9. **Information boundary.** The selector's input structure exposes none of the six prohibited inputs
   enumerated in `METHOD_SPEC_EN.md` §1.2.

## 6. What a PASS does and does not establish

**Does establish:** the implementation computes what the specification defines, on these fourteen cases;
the pairwise relaxation is unsound as a certificate on at least one exhaustively checkable instance; the
soundness asymmetry between Rules A and B is implemented; the commitment rule can change a later choice.

**Does not establish, and must not be reported as establishing:** physical feasibility; runtime
feasibility; that the joint/pairwise discrepancy occurs on realised urban states; that arrival sets can be
computed with a declared approximation direction from a real simulator; protocol-supported assistance;
learned acquisition; benefit of the representation; benefit of commitment; transfer; or novelty.

Master plan §10 states that passing W4 establishes feasibility only under the declared model. W1 is weaker
still: correctness only under the declared **abstraction**.
